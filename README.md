# Level 2

Какой должна быть функция потерь для RM, которая выдаёт распределение вероятностей? Стандартный способ превратить максимизацию вероятности в минимизацию потерь — это взять отрицательный логарифм. Итоговый Loss = -log(P(R_w > R_l))

Какую дополнительную информацию мы можем использовать, если работаем с распределением над оценками? Теперь помимо математического ожидания из распределения мы можем достать дисперсию. Это обогатит сигнал информацией о том, насколько модель уверенна в той или иной оценке.

Я протестил три способа встраивания вероятностной оценки в алгоритм REINFORCE.
Первый - давайте просто брать из распределения математическое ожидание. Логи - {Level_2_prod_RM_expected_value.out}

Второй - давайте помимо математического ожидания ещё будем штрафовать за высокую дисперсию. То есть - Reward(y) = E[P(R|y)] - lambda * Var[P(R|y)]
Где lambda — гиперпараметр. Var[P(R|y)] = E[R^2] - (E[R])^2
Попробовал три значения lambda - [0.1, 0.5, 1.0]. Самым удачным оказался - 0.1. Логи - {Level_2_prod_RM_risk_adjusted_different_lambda.out}

Третий - Вместо вычисления среднего, можно для каждого сгенерированного ответа сэмплировать одну оценку из его распределения P(R|y).
reward = sample_from(P(R|y))
Логи - {Level_2_prod_RM_from_distribution.out}

Все эти способы показали увеличение средней выбиваемой награды на отложенной выборке по сравнению с исходной SFT. Но не такой большой относительный прирост как в первом случае(я сравниваю именно относительные приросты, потому что в зависимости от выбранной RM средняя награда менялась)

Почему так?

Я думаю, потому что датасет HelpSteer2-binarized по своей природе содержит бинарный сигнал предпочтения. Обучение скалярной RM с pairwise loss напрямую оптимизирует под этот сигнал. Попытка восстановить из него полное распределение оценок — это более сложная и, возможно, избыточная задача, которая может вносить артефакты в RM.
